# 已知限制

本页记录当前 Android 版本的真实边界，避免文档承诺超过实现。

## 平台与构建

- 仅提供 Android 实现；当前 APK 为 `arm64-v8a` + `x86_64`。
- 需要 OpenGL ES 3.1；极旧设备或异常驱动可能无法创建上下文。
- Release APK 使用本机 `ImRelighter.jks` 签名；签名材料不纳入 git，换机构建需重新提供。
- 只在 x86_64 SwiftShader 模拟器完成系统化验证；物理 arm64 最终回归仍待完成。

## 图片

- 支持静态 PNG、JPEG、WebP；不支持 GIF、动画 WebP、APNG。
- EXIF 方向支持有限；不做裁剪、旋转、调色。
- 超大图片会采样/缩放以控制内存；具体上限受设备内存影响。
- 原图纹理不生成 mipmap；缩小显示时可能比桌面版略锐/有轻微走样。

## 深度与模型

- 只内置 q4 模型；当前后端只有 CPU，没有 NNAPI/DirectML。
- 只支持单输入/单输出 ONNX；多输入/输出（如 Depth Anything V3）未适配。
- `int8` 模型若包含 CPU 未实现算子会失败。
- 自定义模型类型来自文件名/initializer 推断，不能保证所有导出都可运行。
- 预处理重采样与 Python/PIL 不保证逐像素一致。
- 固定输入尺寸模型需要匹配的预处理配置。

## 渲染

- 最多 8 盏灯；点光/聚光，未提供画笔蒙版或 IBL。
- 阴影使用屏幕空间高度场光线步进 + 模糊，不是物理正确的全局光照。
- 聚光灯的阴影仍使用点光近似，没有独立锥形阴影贴图。
- 拖动灯光时阴影保持全步数但采样数减半，松手后才恢复完整柔和采样；拖动中的阴影边缘会比最终结果略粗。
- 法线目标优先 RGBA16F；不支持 EXT_color_buffer_float 的设备回退 RGBA8，法线精度会下降。
- 预览可降采样；极细阴影在预览中可能不可见，导出为全分辨率。
- 透明像素的合成取决于输入 alpha，未针对 DCC 软件做逐像素对齐。

## 性能与资源

- 首次生成后的第一帧可能因 shader 编译/FBO 分配出现一次停顿。
- 阴影步数/采样数、预览长边、图片分辨率是最主要的性能变量。
- 拖动灯光/阴影参数时使用全步数、半采样的实时阴影预览，松手后更新为完整采样。
- 多任务保存原图/深度/法线 CPU 数据，内存随任务数量线性增长；进程被杀后任务清空。
- SwiftShader 模拟器帧时间不代表真机 GPU 性能。

## 导出

- 深度导出命名为 `_depth16.png`，当前实际写 RGBA8 PNG，不是 16 位深度。
- 一次只导出当前任务/当前视图，不支持批量。
- 导出失败（显存、MediaStore 权限、存储空间）会在状态栏提示。
- 导出不包含 UI 或灯光标记。

## UI

- 竖屏锁定；不支持横屏布局。
- 参数面板为长滚动列表，部分控件在低高度设备上需要多滑几次。
- 触摸采用自定义命中/滚动路由；SwiftShader 截图可能落后一帧，自动化截图的坐标需留余量。
- 主题/语言/模型选择持久化；任务和光照参数仅进程内保存。
