# 测试与验证

## 自动化现状

Android 仓库目前没有桌面版同等的 CTest/GPU 金图像测试套件。原生渲染与 UI 的回归通过构建、模拟器/真机运行和截图对比完成。后续可以补充：

- 深度/法线/光照 Pass 的 GPU 金图像（固定输入、固定参数）。
- `depth_smooth` 的平滑/反转/线条辅助单元回归。
- 多任务切换的 GPU 资源隔离测试。
- 导出 PNG 的像素方向与尺寸验证。

## 构建验证

```powershell
cd android
$env:GRADLE_USER_HOME='D:\Android\.gradle'
.\gradlew.bat assembleDebug --offline --no-daemon
```

期望：`exit=0`，生成 `app/build/outputs/apk/debug/app-debug.apk`；允许 SDK XML 版本警告。

## 模拟器功能清单

在 `emulator-5554`（API 34，x86_64，SwiftShader）上应验证：

1. 启动、导入竖屏与横屏图片。
2. 生成深度/法线，原图→光照自动切换。
3. 光照、法线、深度、阴影、仅光照视图方向与宽高比。
4. 法线强度、表面细节、边缘平滑、线条辅助、反转深度、深度幅度均产生视觉变化。
5. 阴影步进开关：关闭为模糊阴影，开启为原始步进/硬边可见性。
6. 拖动参数时 UI 响应；松手后阴影刷新。
7. 预览长边改变显示分辨率，导出仍为原图分辨率。
8. 两个不同尺寸的任务：切换后各自图片、深度、视图、参数、阴影步进状态正确，无 x 轴压缩/串图。
9. 导出五种视图，PNG 方向正确。
10. Home/返回后进程存活时任务和参数保留；强制停止后恢复空状态。

## 真机验证

物理 `arm64-v8a` 设备需要最终回归：

- 16 KB 页加载、GPU 兼容性（RGBA16F 回退路径）、阴影性能。
- 触摸拖动、滚动惯性、系统栏 inset。
- 相册/模型文件夹 SAF 权限。
- 导出到 `Pictures/ImRelighter`。
- 多任务切换与内存压力。

模拟器只证明功能正确性，不替代真机性能/驱动验证。

## 截图回归

`android/docs/images/` 保存正式文档截图；开发过程截图可放在 `android/dist/`（不纳入正式文档）。截图应使用默认参数，除非文档明确说明正在展示某个参数。

## 已知测试盲区

- 无自动化 GPU 像素比较。
- 无 ONNX 模型矩阵测试；q4 为唯一默认验证模型。
- 无长期多任务/多图内存压力测试。
- SwiftShader 的帧时间不代表真机 GPU 性能。
