# 08 · 风险登记与实施路线

## 风险登记

| 级别 | 风险 | 影响 | 缓解 |
|---|---|---|---|
| 高 | 移动 GPU 对浮点纹理/FBO 支持不一致 | 深度/法线/阴影黑屏或精度异常 | 启动时能力检测；R32F/RGBA16F/RGBA8 分级回退；真机 golden |
| 高 | q4f16 在 arm64 上产生深度噪声 | 法线轮廓密集噪点 | Android 默认 q4；q4f16 仅保留手动兼容 |
| 高 | ARM 设备性能/发热差异大 | 推理慢、掉帧、降频 | q4 + 4 线程；异步推理；质量档位；中端机基准 |
| 中 | 阴影 pass 在移动端成本高 | 帧率下降 | MVP 4 灯、1–2 阴影、1024 贴图、简单 PCF |
| 中 | 大图内存峰值 | OOM/崩溃 | 12MP 上限、分块导出、纹理及时释放 |
| 中 | SAF/URI 与桌面文件路径模型差异 | 打开/导出失败 | `PlatformFiles` 抽象；URI 读入内存；FileProvider |
| 中 | EGL context 丢失 | 纹理/程序失效 | 生命周期状态机；完整资源重建 |
| 中 | 桌面与 Android 代码漂移 | 算法结果不一致 | Android 独立实现 + parity 测试；不反向依赖桌面 |
| 低 | ImGui 触控体验不足 | 操作困难 | 大触控目标、抽屉布局、gesture 层；必要时原生 UI |
| 低 | 安装包体积 | 分发受限 | q4 27MB、arm64-only、AAB/Play Asset Delivery |

## 实施路线

### Phase A · 设计冻结（当前）

- 完成 `android/docs/design`；
- 确认产品范围、渲染预算、模型策略、宿主方案；
- 不写正式源码，不接桌面构建。

**退出条件**：设计文档可支持一名新开发者独立开始实现。

### Phase B · Android 壳与渲染骨架

- Gradle + CMake + Kotlin SurfaceView + EGL；
- ImGui 显示、触摸事件、生命周期；
- 原图纹理和纯色/测试图案渲染；
- 真机 + 模拟器启动。

**退出条件**：连续前后台切换无崩溃，GL 资源正确重建。

### Phase C · 推理与深度/法线

- ORT q4 session、模型资产管理；
- 图片打开/解码/预处理；
- 深度上传、深度分辨率法线、mipmap；
- 原图/深度/法线三视图。

**退出条件**：V2243A 上 q4 结果与验证基线一致，无轮廓噪点。

### Phase D · 灯光与导出

- 灯光模型、材质、法线照明；
- 基础阴影（1–2 灯）；
- PNG 导出/分享；
- 参数持久化。

**退出条件**：单图完整工作流可用，导出与预览一致。

### Phase E · 移动端体验与发布

- 触控手势、抽屉布局、横竖屏/inset；
- 质量档位、错误提示、性能优化；
- 签名 APK/AAB、设备矩阵、发布检查。

**退出条件**：中端 arm64 设备达到性能预算，验收用例通过。

## 里程碑建议

| 里程碑 | 内容 | 验收 |
|---|---|---|
| M0 | 设计完成 | 文档评审通过 |
| M1 | 壳 + GLES + ImGui | 真机显示 UI，生命周期稳定 |
| M2 | q4 推理 + 法线 | 深度/法线正确，无 q4f16 噪点 |
| M3 | 灯光 + 导出 | 单图工作流闭环 |
| M4 | 移动 UX + 发布 | 性能/稳定性/安装包达标 |

## 暂不做

- 多图批处理、云同步、账号体系；
- 桌面工程与 Android 共用 CMake 构建；
- 首版 8 灯全阴影；
- Vulkan 后端；
- 复杂骨骼/动画输入。

这些能力必须在 MVP 稳定后再评估，避免把平台适配和产品扩展混在一起。
